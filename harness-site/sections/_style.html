Design language

Every section draws the same world with the same parts. This page shows each part once, in whichever theme is active, so changes can be reviewed in one place.

The world

The model is a sealed box. The harness is the ring around it. You reach the model only through the Interface, and only Tools reach your files, shell, and APIs. Sections zoom into parts of this picture; they never redraw it differently.

Content roles

Each kind of content has one color, used identically everywhere, and is always labelled. Compaction summaries are also hatched, so they never depend on color.

Context window

A container with a red limit line at the right edge and a dashed compaction threshold. Contents fill from the left in request order.

    Narrative pattern

    Each section opens like this: the visual stays pinned while short steps scroll past. Scroll, or use Next and Back. One block stands for 100 tokens; the numbers are illustrative.

      This is a request. The harness builds it from its system prompt, its tool definitions, and your message.

      The harness sends the whole request to the model. The model reads it and decides what to do next.

      The model asked for a tool. The harness ran it, and appended the model's message and the tool result to the conversation.

      The next request carries everything before it. The model remembers nothing between requests, so all of it is sent again.

      A few tool calls later, each request is several times the size of the first. This is the pattern the agent loop section explores.

      Explanation panel

      Sits beside every sandbox and updates as the student interacts. Plain sentences, one idea at a time.

      Motion rules

      Interface feedback finishes in under 300ms. Explanatory animation runs up to about 2 seconds and is driven by steps, so Back restores the previous state. With reduced motion, scenes jump to their end state.
